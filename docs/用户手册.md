# 投稿前预审质控系统用户手册

本文档面向内部非技术管理员，用于说明如何使用后台页面、`web-review-runner` 和 `sci-pre-review-runner` skills 完成投稿前预审质控任务。

当前推荐工作方式是：后台上传 Word 文稿，复制 **网页端 5.5 thinking 半自动代跑指令** 给 Codex；Codex 使用 Browser 操作你已登录并确认模型的网页端 5.5 thinking，完成 6 个 Agent 双跑、比较器、裁决者和终稿输出；最后把完整输出包粘贴回后台生成 Word/PDF 报告。

## 1. 系统用途

本系统用于临床 SCI 稿件投稿前的结构化预审质控。

系统可以完成：

- 上传单篇 Word 稿件。
- 记录客户信息。
- 运行 Python 文件状态检测，统计图片、表格、图注等材料状态。
- 通过 6 个 Agent 从不同角度进行双轮审稿。
- 每个 Agent 以结构化 JSON 保存问题，并为每条问题生成 `issue_narrative` 长篇审稿正文，便于排查意见是否足够具体。
- 对每个 Agent 的两轮结果进行一致性比较。
- 生成裁决者裁定结果。
- 生成终稿输出。
- 生成可下载的 Word 报告和客户版 PDF 报告。
- 后台下载阶段输出，便于排查各 Agent 的审稿结果。

当前上传文件仅支持 `.doc` / `.docx`，暂不支持 PDF。

## 2. 后台启动与访问

### 2.1 本机启动

在项目目录中启动服务：

```bash
npm install
npm run dev
```

默认访问地址：

- 用户端：http://localhost:3000/
- 后台：http://localhost:3000/admin.html

后台默认账号：

- 用户名：`admin`
- 密码：`Admin@123`

如果已经修改过环境变量 `ADMIN_USERNAME` 或 `ADMIN_PASSWORD`，请使用实际配置的账号密码。

### 2.2 局域网后台模式

如果只希望同事在局域网内使用后台，不开放用户端上传页，可以使用后台-only 模式。

示例启动命令：

```bash
HOST=0.0.0.0 \
APP_EXPOSURE=admin-only \
ALLOWED_HOSTS=localhost,127.0.0.1,192.168.x.x,intron-tools.local \
npm run dev
```

使用时需要把 `192.168.x.x` 替换为运行本系统电脑的局域网 IP。

同事可以访问：

- `http://192.168.x.x:3000/admin.html`
- `http://intron-tools.local:3000/admin.html`

固定域名 `intron-tools.local` 需要通过内网 DNS 或同事电脑的 hosts 文件指向服务器局域网 IP。

注意：

- IP 地址和固定域名是两个不同登录地址，浏览器 Cookie 不共享。
- 使用 IP 登录后，再改用固定域名访问，通常需要重新登录。
- 如果 macOS 防火墙拦截，需要允许 Node 或当前端口的局域网传入连接。
- 后台-only 模式只开放后台页面和后台 API，不开放普通用户端上传入口。

## 3. 后台页面功能总览

后台主要包含三个页面：

- **API 配置**：配置自动调用模型所需的 OpenAI 兼容接口。
- **提示词配置**：维护当前固定调用链的自然语言提示词原文；程序适配层会在运行时自动追加，不显示在文本框中。
- **任务管理**：创建人工代跑任务、查看任务状态、导入 skills 输出、下载报告和阶段输出。

对于当前浏览器半自动代跑流程，最常用的是 **任务管理** 页面。

## 4. 浏览器半自动代跑完整流程

浏览器半自动代跑用于不依赖后台 API 配置、改用网页端 5.5 thinking 模型完成审稿。后台负责上传、解析、生成指令和生成报告；Codex Browser 负责操作网页端模型并整理完整输出包。

### 4.1 操作前准备

开始前请确认：

- 本地后台已经启动，并可访问 `http://localhost:3000/admin.html`。
- Codex 已安装 `web-review-runner` 和 `sci-pre-review-runner` 两个 skill。
- 浏览器中已经打开目标网页端模型页面。
- 你已经完成网页登录、账号验证、模型选择，并确认当前模型是 **5.5 thinking**。
- 待审稿件是 `.doc` 或 `.docx`，不是 PDF。

注意：上传 Word 文稿和发送医学稿件内容属于向第三方网页传输敏感材料。Codex 在执行到上传或发送前会向你确认，确认前不会主动提交。

### 4.2 创建人工代跑任务

1. 打开后台：http://localhost:3000/admin.html
2. 输入管理员账号密码登录。
3. 进入 **任务管理**。
4. 在 **创建人工代跑任务** 区域上传 Word 文稿。
5. 在 **客户信息** 中填写背景信息。

客户信息建议包含：

- 单位
- 科室
- 研究方向
- 目标期刊
- 文章类型
- 特殊关注点

示例：

```text
XX医院，心内科，目标期刊为临床 SCI，文章类型为回顾性队列研究，重点关注统计方法、图表质量和合规风险。
```

6. 点击 **创建人工代跑任务**。
7. 后台会生成任务，并自动打开 **人工代跑工作台**。

### 4.3 复制网页端代跑指令

在 **人工代跑工作台** 中：

1. 查看 **给网页端 5.5 thinking 半自动代跑的指令**。
2. 点击 **复制网页端代跑指令**。
3. 把复制的内容发送给 Codex。

这段指令会包含：

- 原始 Word 文件路径。
- 客户信息。
- 本任务锁定的提示词快照路径。
- `web-review-runner` skill 路径。
- 完整执行要求。

如果暂时不使用网页端模型，也可以复制 **给 Codex 的人工代跑指令**，走普通 `sci-pre-review-runner` 备用流程。

### 4.4 Codex Browser 运行网页端模型

Codex 收到网页端代跑指令后，会使用 `web-review-runner` 流程。你需要配合完成以下事项：

1. Codex 会先读取本地 Word 文件和提示词快照，运行 Python 文件状态检测。
2. Codex 会连接当前浏览器中的网页端模型页面。
3. Codex 会确认网页端是否已经登录，并提醒你确认当前模型为 5.5 thinking。
4. 在第一次上传 Word 或发送稿件内容前，Codex 会明确说明目标网页、模型和文件路径，并等待你确认。
5. 你确认后，Codex 才会上传 Word 文稿并发送对应阶段请求。

网页端模型会按以下顺序运行：

1. Python 文件状态检测和图片/表格/caption 统计。
2. 6 个 Agent 双轮独立审稿，每个 Agent 运行 `run_1` 和 `run_2`。
3. 每个 Agent 的一致性比较。
4. 生成 6 份 Agent 合并问题清单。
5. 生成 `adjudicator_review JSON`，即裁决者裁定。
6. 生成 `final_adjudication JSON`，即终稿输出。
7. 整理完整可粘贴回后台的结果包。

执行过程中请不要手动改动网页端对话内容，除非 Codex 明确要求你处理登录、验证码、模型选择或网页权限弹窗。

### 4.5 输出包内容

完整输出包应包含以下段落：

```text
runner_metadata JSON:
artifact_manifest JSON:
agent_runs:
agent_consistency_reports:
agent_merged_issue_lists:
adjudicator_review JSON:
final_adjudication JSON:
```

其中：

- `runner_metadata JSON`：记录网页端代跑信息，包括 `runner=web-browser`、目标模型、网页地址、上传确认、会话编号和失败重试。
- `artifact_manifest JSON`：Python 文件状态检测结果。
- `agent_runs`：6 个 Agent 的两轮原始输出。
- `agent_consistency_reports`：每个 Agent 的双跑一致性比较。
- `agent_merged_issue_lists`：每个 Agent 合并后的问题清单。
- `adjudicator_review JSON`：裁决者裁定结果。
- `final_adjudication JSON`：终稿输出结果。

不要只复制其中一段，必须复制完整结果包。

### 4.6 粘贴输出并生成报告

回到后台 **人工代跑工作台**：

1. 在 **人工代跑模型标记** 中填写实际使用的模型，例如 `web-5.5-thinking`。
2. 将 Codex 输出的完整结果包粘贴到 **skills 完整输出** 文本框。
3. 点击 **导入输出并生成报告**。
4. 等待任务状态变为 **预审完成**。
5. 点击 **下载 Word 报告** 或 **下载 PDF 报告**。

如果导入失败，通常是以下原因：

- 缺少 `final_adjudication JSON`。
- JSON 格式不完整。
- 粘贴时漏掉了前半部分或后半部分。
- Codex 输出中混入了 Markdown 代码块标记。

遇到失败时，可以让 Codex 重新输出“后台可粘贴的完整 V2.1 结果包”。

### 4.7 中断和续跑建议

网页端模型运行时间较长，尤其是 6 个 Agent 双跑。如果中途失败：

1. 不要删除后台任务。
2. 保留 Codex 已经生成的阶段输出。
3. 告诉 Codex 从失败阶段继续，例如：

```text
请继续刚才的 web-review-runner 任务，从 clinical_methods run_2 开始续跑。已完成的阶段不要重跑，最终仍输出完整后台整包。
```

4. 如果网页端输出不是合法 JSON，让 Codex 只做格式修复，不要重新审稿：

```text
请只修复上一条输出的 JSON 格式，不要新增、删除或改写审稿内容。
```

## 5. 阶段输出下载说明

后台任务列表中可以下载阶段输出，用于排查 Agent 结果。

阶段输出分为三类：

1. **六 Agent 双跑与一致性比较**
   - 包含 6 个 Agent 的 `run_1` 和 `run_2`。
   - 包含每个 Agent 的一致性比较结果。
   - 包含每个 Agent 的合并问题清单。
   - 优先展示每条问题的 `issue_narrative` 长篇审稿正文，再展示位置、证据和建议等结构化字段。

2. **裁决者裁定**
   - 对 6 个 Agent 合并问题清单进行裁决。
   - 合并重复问题。
   - 调整严重程度。
   - 保留或排除问题，并记录理由。

3. **终稿输出**
   - 面向客户报告的最终文字内容。
   - 后台 Word/PDF 报告主要基于这一部分生成。

阶段输出主要用于内部排查，不建议直接发给客户。

## 6. skills 打包方法

### 6.1 需要打包的目录

固定打包以下目录：

```text
skills/sci-pre-review-runner
skills/web-review-runner
```

该目录必须包含：

```text
skills/sci-pre-review-runner/SKILL.md
skills/sci-pre-review-runner/references/prompts.json
skills/sci-pre-review-runner/scripts/build_review_context.mjs
skills/sci-pre-review-runner/scripts/export_prompts_from_project.mjs
skills/sci-pre-review-runner/scripts/validate_final_json.mjs
skills/web-review-runner/SKILL.md
```

### 6.2 不要打包的内容

不要把以下内容放进 skills 压缩包：

- `storage/`
- `.data/`
- 上传的客户稿件
- 已生成的 Word/PDF 报告
- 数据库文件
- API Key
- 代理配置
- 任何客户隐私材料

这两个 skills 本身不包含 API Key，不负责生成报告，也不会读取后台 API 配置。`web-review-runner` 只负责协助操作你已登录的网页端模型，并在上传或发送稿件前要求你确认。

### 6.3 使用 Finder 打包

适合非技术管理员：

1. 打开项目目录。
2. 进入 `skills` 文件夹。
3. 同时选中 `sci-pre-review-runner` 和 `web-review-runner` 两个文件夹。
4. 右键点击所选文件夹。
5. 选择 **压缩 2 项**。
6. 得到一个压缩包，建议重命名为 `intron-review-skills.zip`。

压缩包发给同事即可。

### 6.4 使用命令行打包

适合熟悉终端的人员：

```bash
cd "<项目目录>/skills"
zip -r "$HOME/Desktop/intron-review-skills.zip" sci-pre-review-runner web-review-runner -x "*.DS_Store"
```

生成的压缩包位置：

```text
~/Desktop/intron-review-skills.zip
```

## 7. 在 Codex 中安装 skills

### 7.1 安装位置

Codex 本地 skills 推荐放在：

```text
~/.codex/skills/
```

安装后的目录结构必须是：

```text
~/.codex/skills/sci-pre-review-runner/SKILL.md
~/.codex/skills/sci-pre-review-runner/references/prompts.json
~/.codex/skills/sci-pre-review-runner/scripts/build_review_context.mjs
~/.codex/skills/web-review-runner/SKILL.md
```

注意：`SKILL.md` 必须直接位于对应 skill 文件夹下面。不要出现下面这种多套了一层目录的情况：

```text
~/.codex/skills/sci-pre-review-runner/sci-pre-review-runner/SKILL.md
~/.codex/skills/web-review-runner/web-review-runner/SKILL.md
```

### 7.2 使用 Finder 安装

1. 解压 `intron-review-skills.zip`。
2. 在 Finder 中按 `Command + Shift + G`。
3. 输入：

```text
~/.codex/skills
```

4. 如果没有 `skills` 文件夹，就手动新建。
5. 将解压后的 `sci-pre-review-runner` 和 `web-review-runner` 两个文件夹放入 `~/.codex/skills/`。
6. 如果已有旧版本，可以先把旧文件夹改名为 `sci-pre-review-runner_backup`、`web-review-runner_backup`，再放入新版本。
7. 重启 Codex，或开启新的 Codex 会话。

### 7.3 使用命令行安装

假设压缩包在桌面：

```bash
mkdir -p "$HOME/.codex/skills"
unzip "$HOME/Desktop/intron-review-skills.zip" -d "$HOME/.codex/skills"
```

如果之前已经安装过同名 skill，建议先备份旧版本：

```bash
mv "$HOME/.codex/skills/sci-pre-review-runner" "$HOME/.codex/skills/sci-pre-review-runner_backup"
mv "$HOME/.codex/skills/web-review-runner" "$HOME/.codex/skills/web-review-runner_backup"
unzip "$HOME/Desktop/intron-review-skills.zip" -d "$HOME/.codex/skills"
```

### 7.4 验证安装是否成功

在新的 Codex 会话中输入：

```text
请使用 web-review-runner skill，通过网页端 5.5 thinking 对这篇 Word 稿件进行投稿前预审半自动代跑。
```

如果 Codex 能识别该 skill，能说明需要你登录网页端模型并在上传 Word 前确认，且最终会输出 `runner_metadata JSON`、`artifact_manifest JSON`、6 个 Agent 结果、`adjudicator_review JSON` 和 `final_adjudication JSON`，说明安装成功。

如果 Codex 提示找不到 skill，优先检查：

- 文件夹是否放在 `~/.codex/skills/` 下。
- `SKILL.md` 是否直接位于 `sci-pre-review-runner` 或 `web-review-runner` 文件夹内。
- 是否重启了 Codex 或开启了新会话。
- 是否把压缩包解压成了双层目录。

## 8. 提示词配置与版本管理

后台 **提示词配置** 页面用于维护当前调用链的自然语言提示词原文。系统会在模型调用、任务提示词快照和 skill 导出时自动追加程序适配层，用于保证 JSON schema、`issue_narrative`、比较器、裁决者和终稿输出能被后台解析；适配层不会写入后台文本框。

当前维护的提示词包括：

- 全局系统提示词
- Agent 1：选题创新预审
- Agent 2：临床方法预审
- Agent 3：统计结果预审
- Agent 4：数值审计预审
- Agent 5：图表与视觉材料审计
- Agent 6：投稿安全与表达预审
- 通用一致性比较器
- 裁决者裁定
- 终稿输出

V1 历史提示词已在后台隐藏，但历史数据仍保留。

### 8.1 修改提示词

1. 进入 **提示词配置**。
2. 在 **调用点** 中选择要修改的提示词。
3. 在右侧文本框编辑提示词内容。
4. 点击 **提交为草稿**。
5. 在版本历史中检查草稿。
6. 确认无误后点击 **发布**。

只有发布版本会用于新任务。

新任务锁定的 `prompt_snapshot` 中，`content` 是模型实际看到的“提示词原文 + 程序适配层”；同时记录 `rawContentHash`、`adapterVersion` 和 `effectiveContentHash`，方便区分自然语言提示词质量与程序格式约束。

### 8.2 回滚提示词

如果新版本效果不好：

1. 在版本历史中找到旧版本。
2. 点击 **回滚**。
3. 后续新任务会使用回滚后的提示词。

已经创建的任务会锁定当时的提示词快照，不会因为后台后续修改提示词而自动变化。

### 8.3 删除历史版本

后台支持删除非当前发布版本。删除前请确认该版本不再需要用于排查。

## 9. API 配置说明

API 配置用于自动审稿模式。人工代跑模式不依赖后台 API 配置，因此即使没有配置 API，也可以使用人工代跑完成审稿。

API 配置字段包括：

- 配置名称
- Base URL
- 代理地址
- API Key
- 模型名
- timeout
- temperature
- temperature 参数策略
- reasoning effort
- max tokens
- max token 参数名
- 是否生效

注意：

- 同一时间只允许一个 API 配置生效。
- API Key 会由后端加密保存。
- 如果使用 OpenAI `gpt-5*` 或 `o*` 模型，系统会在自动模式下优先使用 `max_completion_tokens`。
- 如果模型不支持 `temperature`，可使用自动策略避免报错。
- 如果使用本机代理，常见填写方式为 `http://127.0.0.1:7890`。
- 当前代理地址不支持 `socks5://`。

如果后台提示连接测试失败，优先检查：

- API Key 是否正确。
- Base URL 是否正确。
- 模型名是否正确。
- 代理地址是否能被 Node 后端访问。
- 当前网络是否允许访问模型接口。
- `max_tokens` / `max_completion_tokens` 参数是否与模型匹配。

## 10. 任务管理说明

任务管理页可以完成：

- 创建人工代跑任务。
- 查看任务状态。
- 查看摘要或错误原因。
- 打开人工代跑工作台。
- 下载阶段输出。
- 下载 Word 报告。
- 下载 PDF 报告。
- 重试失败任务。
- 取消未完成任务。

### 10.1 常见任务状态

常见状态含义：

- `queued`：排队中。
- `parsing`：解析材料中。
- `stage1_running`：GPT 预审组审稿中。
- `stage2_running`：终稿输出生成中。
- `docx_generating`：生成质控报告中。
- `succeeded`：预审完成。
- `failed`：预审失败。
- `cancelled`：任务已取消。
- `manual_stage_pending`：等待人工代跑输出。
- `manual_final_pending`：等待人工终稿输出。

### 10.2 Word/PDF 报告

任务成功后，后台会显示：

- Word 报告下载按钮
- PDF 报告下载按钮

Word 报告适合内部编辑和二次修改。

PDF 报告适合客户交付，包含客户版可视化内容，例如六维评分、问题分布和核心问题摘要。

### 10.3 阶段输出

阶段输出用于内部排查，不建议直接交付客户。

如果客户质疑报告内容，管理员可以下载阶段输出，查看：

- 哪个 Agent 提出了该问题。
- 两轮审稿是否都识别到该问题。
- 一致性比较是否保留了该问题。
- 裁决者是否调整或排除了该问题。
- 终稿输出如何转写为客户报告文字。

## 11. 常见问题排查

### 11.1 后台打不开

检查：

- 服务是否启动。
- 端口是否为 `3000`。
- 浏览器地址是否为 `http://localhost:3000/admin.html`。
- 局域网访问时，是否使用了正确的服务器 IP。
- macOS 防火墙是否阻止了 Node。

### 11.2 登录失败

检查：

- 默认用户名是否为 `admin`。
- 默认密码是否为 `Admin@123`。
- 是否修改过环境变量 `ADMIN_USERNAME` 或 `ADMIN_PASSWORD`。
- 是否用 IP 和固定域名切换访问导致需要重新登录。

### 11.3 上传失败

检查：

- 文件是否为 `.doc` 或 `.docx`。
- 当前系统暂不支持 PDF。
- 文件是否正在被 Word 占用。
- 文件是否损坏。
- `.doc` 解析能力有限，建议转换为 `.docx` 后再上传。

### 11.4 Codex 找不到 skill

检查：

- 是否已经安装到 `~/.codex/skills/sci-pre-review-runner` 和 `~/.codex/skills/web-review-runner`。
- `SKILL.md` 是否直接在对应目录下。
- 是否重启 Codex 或开启新会话。
- 是否安装成了双层目录。

### 11.5 粘贴 skills 输出后导入失败

检查：

- 是否包含完整输出包。
- 是否缺少 `final_adjudication JSON`。
- 是否缺少 `adjudicator_review JSON`。
- 是否缺少 `artifact_manifest JSON`、`agent_runs`、`agent_consistency_reports` 或 `agent_merged_issue_lists`。
- JSON 是否被代码块标记包裹。
- 是否只复制了部分 Agent 输出。

`runner_metadata JSON` 用于记录网页端代跑信息，建议保留；如果缺少它，通常不影响报告生成。

可以让 Codex 重新输出：

```text
请重新输出可粘贴回后台的完整 V2.1 结果包，不要使用 Markdown 代码块，不要省略任何 JSON 段落。
```

### 11.6 Word 报告无法打开

一般可能由异常字符或生成过程失败导致。

处理方式：

- 回到后台重新生成报告。
- 检查客户信息中是否粘贴了异常控制字符。
- 如果仍失败，下载阶段输出并保留任务 ID，交给系统维护人员排查。

### 11.7 PDF 报告无法打开

检查：

- 任务是否已经成功。
- 后台是否显示 PDF 下载按钮。
- 服务器是否能正常生成 PDF。
- 如果 PDF 缺失但 Word 正常，保留任务 ID 交给系统维护人员排查 PDF 生成模块。

## 12. 浏览器自动化日常操作指南

本章按一次真实交付任务来写。建议管理员每次都按这个顺序操作，减少漏步骤和混用流程。

### 12.1 一次完整交付的标准流程

1. 启动后台。

```bash
npm run dev
```

2. 打开后台并登录。

```text
http://localhost:3000/admin.html
```

3. 打开网页端模型页面，在浏览器中完成登录、账号验证和模型选择。

确认当前模型是 **5.5 thinking**。如果网页端需要新建对话，先打开一个空白对话，但不要手动上传 Word。

4. 回到后台 **任务管理**，在 **创建人工代跑任务** 中上传 Word 文稿并填写客户信息。

客户信息越具体，终稿越容易贴合交付目标。至少建议写清单位/科室、研究类型、目标期刊、重点关注点。

5. 点击 **创建人工代跑任务**。

后台会解析 Word、保存任务、生成提示词快照，并进入 **人工代跑工作台**。

6. 在工作台点击 **复制网页端代跑指令**。

复制的是给 Codex 的指令，不是直接粘贴到网页端模型里的提示词。

7. 把指令发送给 Codex，并明确让 Codex 使用 `web-review-runner`。

示例：

```text
请使用 web-review-runner，按照下面的网页端代跑指令执行。每次上传 Word 或发送稿件内容前先向我确认。
```

8. Codex 会读取本地任务文件、连接浏览器页面，并在第一次上传 Word 或发送稿件内容前请求你确认。

确认前，请检查三点：

- 文件路径是否是本次要审的 Word。
- 目标网页是否是你已登录的模型页面。
- 当前模型是否确认为 5.5 thinking。

9. 确认后等待 Codex 自动运行。

运行期间会依次完成 6 个 Agent 双跑、一致性比较、裁决者裁定和终稿输出。不要手动编辑网页端对话内容，除非 Codex 要求你处理登录、验证码、权限弹窗或模型选择。

10. Codex 完成后，会输出后台可导入的完整结果包。

完整结果包应包含：

```text
runner_metadata JSON:
artifact_manifest JSON:
agent_runs:
agent_consistency_reports:
agent_merged_issue_lists:
adjudicator_review JSON:
final_adjudication JSON:
```

11. 回到后台 **人工代跑工作台**。

在 **人工代跑模型标记** 中填写：

```text
web-5.5-thinking
```

12. 把完整结果包粘贴到 **skills 完整输出** 文本框。

不要只粘贴终稿 JSON，也不要粘贴 Markdown 代码块外壳。

13. 点击 **导入输出并生成报告**。

任务成功后状态会变为 **预审完成**。

14. 下载报告。

- **Word 报告**：适合内部编辑、二次加工。
- **PDF 报告**：适合客户交付和正式展示。

15. 如需排查质量，下载 **阶段输出**。

阶段输出是内部调试文件，不建议直接发给客户。

### 12.2 每一步应该看到什么

- 创建任务后，后台应打开 **人工代跑工作台**，并显示网页端代跑指令。
- Codex 开始代跑后，应先说明将使用 `web-review-runner`，并要求你确认上传或发送稿件。
- 网页端模型运行时，应出现多个独立阶段的对话或请求，不应把所有 Agent 混在同一个上下文里连续追问。
- Codex 最终输出应是一整包文本，而不是单独一段报告正文。
- 后台导入成功后，应同时出现 Word 和 PDF 下载按钮。

### 12.3 中断后的处理

如果网页端模型卡住、刷新、输出中断或 JSON 不合法，不要立刻新建任务。

优先这样处理：

```text
请继续刚才的 web-review-runner 任务，从中断的阶段继续。已完成阶段不要重跑，最终仍输出完整后台整包。
```

如果只是 JSON 格式坏了，用这句话：

```text
请只修复上一条输出的 JSON 格式，不要新增、删除或改写审稿内容。
```

如果只得到部分结果包，用这句话：

```text
请基于已完成内容，重新整理一份可粘贴回后台的完整结果包，包含 runner_metadata、artifact_manifest、agent_runs、agent_consistency_reports、agent_merged_issue_lists、adjudicator_review JSON 和 final_adjudication JSON。
```

只有在原 Word 文件、客户信息或提示词版本确实需要改变时，才建议重新创建后台任务。

### 12.4 不要做的事

- 不要把 Word 原稿直接拖到网页端模型里手动问，除非这是 Codex 要求并且你已确认的步骤。
- 不要把阶段输出 TXT 发给客户。
- 不要把不同任务的 Agent 输出、裁决者输出和终稿输出混在一起导入。
- 不要把 `sci-pre-review-runner` 普通代跑结果和 `web-review-runner` 网页端结果混合到同一个任务的同一阶段。
- 不要在网页端模型输出不完整时，只复制看起来像报告的那一段回后台。

### 12.5 什么时候使用普通 skill 备用流程

以下情况可以临时使用 `sci-pre-review-runner` 普通代跑流程：

- 网页端模型无法登录。
- Browser 自动化无法稳定操作当前网页。
- 网页端模型暂时没有 5.5 thinking 可选。
- 只需要内部快速测试提示词、导入格式或报告生成链路。

普通 skill 备用流程质量可能低于网页端 5.5 thinking，正式客户交付建议优先使用浏览器自动化流程。

## 13. 安全注意事项

- 不要把 API Key 写入手册、聊天记录或 skills 压缩包。
- 不要把客户原始稿件放入 skills 压缩包。
- 不要把 `.data/`、`storage/`、报告文件夹一起发给同事。
- 局域网后台模式只适合内部可信网络使用。
- 当前后台是单管理员账号，不适合多人权限隔离场景。
- 阶段输出包含内部审稿过程，不建议直接给客户。
